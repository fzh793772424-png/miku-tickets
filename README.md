# miku-tickets

Magical Mirai 2027 团队票务看板，使用 GitHub Pages 和 Supabase。

## 本地检查

无需安装依赖，使用 Node.js 运行：

```sh
node --test tests/reliability.test.cjs
```

检查覆盖音乐播放状态、资源引用、分页读取、备份完整字段、备份失败、座位重叠、重复提交、编辑保护和过期响应。测试使用模拟数据，不连接生产数据库。

发布时需一起保留 `index.html`、`board-utils.js`、`workflow.css`、`1.JPG`、`2.JPG`、`bgm.mp3`。

## 日常操作与显示

- 页面使用紧凑的初音主题横幅、统一的表格和手机票据卡片。
- “只看我的票”“待分配”可组合筛选；清除筛选恢复全部。复制和 CSV 导出采用与列表相同的筛选及排序。
- 备注可换行，支持 Ctrl / Command + Enter 保存。失败时保留草稿。
- 普通字段修改、备注、转票和退票提交时核对已读取的票据字段；数据改变、权限拒绝或记录删除时不再把零行更新当成保存成功。这不是跨多步操作的事务。
- 全员操作日志和单票历史使用日本时间，显示完整年月日及秒；不改变数据库时间。
- 合并前检查场馆、区域、归属、状态、买家、备注、原持有人及币种，避免静默丢失不同信息。

这批页面改动无需运行新 SQL。浏览器实测仍需在发布后进行。

## 备份范围

- “导出筛选结果”导出当前场馆内符合筛选的已加载票据，包括系统标记和手写备注，适合查看。
- “备份票据与历史”重新分页读取当前账号有权限查看的 `tickets` 和 `ticket_logs`，保存所有返回字段为 JSON。
- JSON 包含原始 ID、票号、关联字段、备注和日志，但不包含 Auth 账号、密码、成员表、表结构或权限规则。
- 这是多个读取请求的结果，不是数据库一致性快照；备份期间应请成员暂停修改。任一读取失败均不生成文件。
- 页面尚未提供自动恢复。恢复需由管理员核对数据库结构、外键和 ID 序列后处理，勿直接向现有数据追加。

## 仍需数据库端完成的工作

`sql/002_ticket_permissions.sql` 包含票据及日志权限规则，需在 Supabase 独立执行；合并网页代码不会自动执行 SQL。权限回归测试在 `tests/permissions.test.mjs`。以下事项仍需后续处理：

1. **事务**：拆票、合票和清空仍由多个请求组成，后续步骤失败可能留下部分结果。应迁移到经过权限检查的数据库事务 / RPC，并将日志写入同一事务。
2. **逐座位唯一约束**：前端检查每张连票中是否存在重叠座位，但 `uniq_key` 仍按整组座位计算。并发用户可以同时通过前端检查，需要数据库按场次、区域、单个座位约束唯一性。
3. **权限后续**：现有迁移沿用登录邮箱和票据 BY 标记；后续可迁移至稳定的用户 ID。成员公开读取和既有 RPC 的权限未在该迁移中收紧。日志内容仍由前端提交，并非不可伪造的审计记录。
4. **编辑冲突**：单票常用修改已核对原字段，但拆合票和批量修改仍需服务端版本及事务控制。

本次改动没有执行数据库迁移，也没有在生产环境创建、修改或删除票据。
