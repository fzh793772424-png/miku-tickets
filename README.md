# miku-tickets

Magical Mirai 2027 团队票务看板，使用 GitHub Pages 和 Supabase。

## 本地检查

无需安装依赖，使用 Node.js 运行：

```sh
node --test tests/reliability.test.cjs
```

检查覆盖音乐播放状态、资源引用、分页读取、备份完整字段、备份失败、座位重叠、重复提交、编辑保护和过期响应。测试使用模拟数据，不连接生产数据库。

发布时需一起保留 `index.html`、`board-utils.js`、`1.JPG`、`2.JPG`、`bgm.mp3`。

## 备份范围

- “导出 CSV”导出当前场馆的已加载票据，包括系统标记和手写备注，适合查看。
- “备份票据与历史”重新分页读取当前账号有权限查看的 `tickets` 和 `ticket_logs`，保存所有返回字段为 JSON。
- JSON 包含原始 ID、票号、关联字段、备注和日志，但不包含 Auth 账号、密码、成员表、表结构或权限规则。
- 这是多个读取请求的结果，不是数据库一致性快照；备份期间应请成员暂停修改。任一读取失败均不生成文件。
- 页面尚未提供自动恢复。恢复需由管理员核对数据库结构、外键和 ID 序列后处理，勿直接向现有数据追加。

## 仍需数据库端完成的工作

仓库没有 Supabase migrations 或权限策略，以下事项尚未验证或修改：

1. **事务**：拆票、合票和清空仍由多个请求组成，后续步骤失败可能留下部分结果。应迁移到经过权限检查的数据库事务 / RPC，并将日志写入同一事务。
2. **逐座位唯一约束**：前端检查每张连票中是否存在重叠座位，但 `uniq_key` 仍按整组座位计算。并发用户可以同时通过前端检查，需要数据库按场次、区域、单个座位约束唯一性。
3. **权限**：需确认 tickets、ticket_logs、members 的 RLS，成员归属应绑定 `auth.uid()`，禁止普通用户提升 `is_admin` 或更改其他人的票。页面上的按钮限制不能替代数据库权限。
4. **编辑冲突**：此次避免刷新打断输入，但没有实现数据库版本检查；多人修改同一字段仍可能相互覆盖。

本次改动没有执行数据库迁移，也没有在生产环境创建、修改或删除票据。
